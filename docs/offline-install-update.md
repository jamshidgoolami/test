# نصب و بروزرسانی آفلاین (ویندوز x64)

این سند برای محیط‌هایی است که **سیستم مقصد به اینترنت دسترسی ندارد**: ساخت یک
بستهٔ کامل روی یک سیستم آنلاین، انتقال آن (فلش/شبکهٔ قفل‌شده) و نصب یا
**بروزرسانی با حفظ داده‌ها** روی سیستم ویندوز ۶۴بیت.

اسکریپت‌ها:

| فایل                      | کجا اجرا می‌شود       | کار                                           |
| ------------------------- | --------------------- | --------------------------------------------- |
| `npm run offline:prepare`  | سیستم آنلاین          | ساخت بستهٔ نصب (سورس + کش وابستگی‌ها + آرشیو) |
| `npm run offline:portable` | سیستم آنلاین          | ساخت بستهٔ Portable با Node و وابستگی‌های آماده |
| `install.cmd`              | سیستم آفلاین (ویندوز) | نصب اولیه از روی کش محلی + ساخت رابط کاربری   |
| `update.cmd <مسیر نصب>`    | سیستم آفلاین (ویندوز) | بروزرسانی کد با **حفظ کامل داده‌ها**          |
| `NetWatch.cmd`             | سیستم آفلاین (ویندوز) | اجرای بستهٔ Portable بدون Node/npm نصب‌شده     |

منبع اسکریپت‌ها: [`scripts/offline/`](../scripts/offline/) — توضیح فنی هر فایل در
سر خودِ همان فایل است.

---

## روش Portable (بدون نصب Node.js روی مقصد)

اگر سیستم مقصد حتی Node.js هم ندارد، بستهٔ Portable را بسازید:

```bash
npm run offline:portable
```

خروجی:

```
.offline/
  netwatch-portable-<version>-win64/          پوشهٔ آمادهٔ اجرا
  netwatch-portable-<version>-win64.tar.gz    آرشیو برای انتقال
```

این بسته شامل `node.exe` ویندوز x64، همهٔ وابستگی‌های Production و رابط
کاربری Build‌شده است. روی سیستم آفلاین فقط آرشیو را باز کنید و روی
`NetWatch.cmd` دابل‌کلیک کنید؛ نیازی به نصب Node.js، npm، Build یا اینترنت
نیست. داده‌ها در پوشهٔ `data` کنار برنامه ساخته می‌شوند.

برای بروزرسانی، برنامه را ببندید و محتوای بستهٔ جدید را روی همان پوشه کپی
کنید. بستهٔ جدید هیچ پوشهٔ `data` ندارد؛ بنابراین دادهٔ فعلی دست‌نخورده
می‌ماند. Migration پایگاه‌داده در اولین اجرا خودکار است.

> بستهٔ Portable نیز فقط برای **ویندوز ۶۴بیت** است. `node.exe` داخل آن از
> توزیع رسمی Node.js (شاخهٔ ۲۲ LTS) گرفته می‌شود و checksum آن هنگام ساخت
> بررسی می‌شود.

## ۱. پیش‌نیازها

| سیستم | نیاز |
| --- | --- |
| سیستم آنلاین (سازندهٔ بسته) | Node.js `>= 22.12` و دسترسی اینترنت (فقط برای ساخت بسته) |
| سیستم آفلاین (مقصد) | **ویندوز ۶۴بیت** + Node.js `>= 22.12` نصب‌شده؛ به اینترنت نیازی نیست |

> هیچ‌یک از مراحل به Docker، کامپایلر، Python یا MSVC نیاز ندارد؛ همهٔ باینری‌های
> لازم (برای ویندوز x64) از قبل داخل بسته است.

## ۲. ساخت بسته روی سیستم آنلاین

```bash
cd <پوشهٔ پروژه>
npm run offline:prepare
```

خروجی:

```
.offline/
  netwatch-offline-<version>-win64/          پوشهٔ نصب (قابل استفادهٔ مستقیم)
  netwatch-offline-<version>-win64.tar.gz    آرشیو فشرده برای انتقال
```

این دستور به‌ترتیب:

1. سورس برنامه را کپی می‌کند؛ **بدون** `node_modules`، **بدون** `data/`
   (پایگاه‌داده و پشتیبان‌ها)، **بدون** `.git`، **بدون** فایل‌های `.env`،
   `.cloud-attachments` و لاگ‌ها. یعنی هیچ داده یا Secretی از سیستم شما وارد بسته
   نمی‌شود.
2. با `npm ci --os=win32 --cpu=x64` همهٔ وابستگی‌ها را برای **ویندوز x64** داخل
   کش اختصاصی `.npm-cache` دانلود می‌کند — از جمله بسته‌های باینری مثل
   `@node-rs/argon2-win32-x64-msvc`، `@rolldown/binding-win32-x64-msvc` و
   `lightningcss-win32-x64-msvc`.
3. **آزمون واقعی** انجام می‌دهد: یک نصب کامل با `npm ci --offline` (بدون شبکه) و
   راستی‌آزمایی وجود تک‌تک بسته‌های باینری ویندوز. اگر حتی یک بسته کم باشد، همین
   جا با پیام دقیق متوقف می‌شود؛ چون npm بستهٔ اختياریِ ناسازگار را **بی‌صدا**
   رد می‌کند و «خروجی صفر» به‌تنهایی دلیل سالم‌بودن نیست.
4. `node_modules` آزمایشی را حذف و آرشیو `tar.gz` را می‌سازد.

> اگر `tar` روی سیستم سازنده نبود، آرشیو ساخته نمی‌شود ولی **خودِ پوشه آماده است**
> و می‌توانید آن را کپی کنید. پس از هر تغییر در وابستگی‌ها (`package.json` /
> `package-lock.json`) بسته را **دوباره** بسازید.

## ۳. انتقال و نصب روی سیستم آفلاین

1. فایل `netwatch-offline-<version>-win64.tar.gz` را به ویندوز منتقل کنید.
2. باز کنید: در ویندوز ۱۱ روی فایل راست‌کلیک ← Extract، یا از خط فرمان:

   ```bat
   tar -xzf netwatch-offline-1.4.1-win64.tar.gz
   ```

3. داخل پوشهٔ بازشده، `install.cmd` را اجرا کنید (دابل‌کلیک کافی است).

   ```bat
   cd netwatch-offline-1.4.1-win64
   install.cmd
   ```

   مراحل: بررسی Node ← `npm ci --offline` از `.npm-cache` محلی ← `npm run build` ←
   راستی‌آزمایی بسته‌های باینری و ساخت رابط کاربری.

4. اجرا:

   ```bat
   npm start
   ```

   مرورگر: `http://localhost:8787`

**انتشار در شبکهٔ داخلی:** سرور پیش‌فرض فقط روی `127.0.0.1` گوش می‌دهد؛ برای دسترسی
از سایر دستگاه‌ها:

```bat
set HOST=0.0.0.0
npm start
```

(در ویندوز می‌توانید همین متغیر را در Environment variables سیستم هم ثبت کنید تا
با هر بار اجرای `npm start` اعمال شود.)

## ۴. بروزرسانی با حفظ داده‌ها ← روش پیشنهادی

**اصل کار:** داده‌ها به‌طور پیش‌فرض در `data/` نگهداری می‌شوند (`netwatch.db`،
پشتیبان‌ها، نقشه‌های `mbtiles`، گواهی‌های `tls`). اگر `NETWATCH_DATA_DIR` یا
`NETWATCH_DB` در محیط تنظیم شده باشد، اسکریپت همان مسیر را برای تشخیص و پشتیبان
استفاده می‌کند. اسکریپت بروزرسانی **هرگز** به داده دست نمی‌زند؛ فقط کد
(`package.json`، `package-lock.json`، `server/`، `web/`، `scripts/`، `docs/` و…)
جایگزین می‌شود.

### مراحل

```bat
:: ۱) توقف برنامه (Ctrl+C در همان پنجره، یا توقف سرویس)

:: ۲) باز کردن بستهٔ جدید در یک پوشهٔ جداگانه (مهم: پوشهٔ نصب قبلی نباشد)
tar -xzf netwatch-offline-1.4.1-win64.tar.gz

:: ۳) اجرای بروزرسانی از داخل همان بستهٔ جدید، با اشاره به پوشهٔ نصب فعلی
cd netwatch-offline-1.4.1-win64
update.cmd C:\NetWatch
```

اسکریپت `update.mjs` به‌ترتیب این کارها را می‌کند و در **هر گام که خطا بدهد،
همان‌جا متوقف می‌شود** (پیش از ادامهٔ مخرب):

| # | مرحله | خروجی |
| --- | --- | --- |
| ۱ | بررسی اینکه پوشهٔ مقصد واقعاً نصب NetWatch است و برنامه روی پورت در حال اجرا نیست | خطای زودهنگام به‌جای کپی روی سرویسِ روشن |
| ۲ | **پشتیبان از پایگاه‌داده** با `npm run db:backup` | پوشهٔ پشتیبان تأییدشده + Manifest |
| ۳ | کپی کد جدید روی نصب موجود (با ردشدن `data/`، `node_modules/`، `.npm-cache/`، `.git/`، `.env`) | نسخهٔ برنامه ارتقا می‌یابد |
| ۴ | `npm ci --offline` از کشِ همین بسته | وابستگی‌ها طبق `package-lock` جدید هم‌تراز می‌شوند |
| ۵ | `npm run build` + راستی‌آزمایی | `web/dist` تازه و تأیید بسته‌های باینری |

> اگر پایگاه‌داده وجود داشته باشد ولی `node_modules` موجود نباشد، اسکریپت پیش از
> هر تغییری متوقف می‌شود؛ چون بدون وابستگی‌ها نمی‌تواند پشتیبان **تأییدشده** بسازد.
> ابتدا در همان نصب `install.cmd` را اجرا کنید و سپس بروزرسانی را تکرار کنید.

خروجی پایانی نسخهٔ قدیم و جدید، مسیر پشتیبان و دستور اجرا را نشان می‌دهد؛ سپس:

```bat
cd C:\NetWatch
npm start
```

### گزینه‌ها

| گزینه | کاربرد |
| --- | --- |
| `--ignore-running` | ادامهٔ کار حتی اگر چیزی روی پورت برنامه (پیش‌فرض `8787`، یا `PORT`) گوش می‌دهد |
| `--no-build` | ردکردن مرحلهٔ ساخت (فوق‌العاده؛ فقط وقتی مطمئنید `web/dist` به‌روز است) |
| `--cache <dir>` | استفاده از کش npm دیگری به‌جای `.npm-cache` همین بسته |

### بازگشت (Rollback)

1. برنامه را متوقف کنید.
2. پشتیبان ساخته‌شده را بازیابی کنید (اگر `NETWATCH_DATA_DIR` سفارشی است،
   مسیر همان پوشه را بدهید):

   ```bat
   npm run db:restore -- data\backups\netwatch-20261031-055606-672498
   ```

3. بستهٔ **قبلی** را با همان دستور `update.cmd <مسیر نصب>` دوباره اجرا کنید.

> اجرای کد قدیمی روی پایگاه‌دادهٔ ارتقایافته پشتیبانی نمی‌شود؛ همیشه اول
> پشتیبان را برگردانید. جزئیات Migrationها: [upgrade.md](upgrade.md).

### نکته‌ها

- **نسخهٔ جدید فایلی را حذف نمی‌کند:** اگر نسخهٔ تازه فایلی از کد را کنار گذاشته
  باشد، آن فایل در پوشهٔ نصب باقی می‌ماند (بی‌ضرر است؛ برای پاک‌سازی کامل، نصب
  را از صفر با همان `install.cmd` روی یک کپی از `data/` انجام دهید).
- **پشتیبانِ منظم:** `npm run db:backup` — یا فعال‌کردن پشتیبان خودکار از
  «تنظیمات ← پشتیبان‌گیری». سیاست و بازیابی: [backup-restore.md](backup-restore.md).
- **بروزرسانی همیشه به اینترنت ندارد؛** همهٔ tarballها داخل `.npm-cache` همان
  بسته است.

## ۵. تنظیماتی که بعد از نصب/بروزرسانی باید ببینید

### رفع خطای `NOT_IN_ALLOWLIST` در Probe

اگر هنگام Ping/بررسی چنین خطایی دیدید:

```
Probe به مقصد 28.128.126.17 مجاز نیست (NOT_IN_ALLOWLIST)؛ محدودهٔ مقاصد مجاز
را در تنظیمات یا NETWATCH_PROBE_ALLOWED_CIDRS بررسی کنید.
```

یعنی آدرس مقصد خارج از محدودهٔ مجاز Probe است (پیش‌فرض: شبکه‌های خصوصی و
loopback). رفع:

1. وارد شوید → **تنظیمات ← موتور مانیتورینگ ← «محدودهٔ مقاصد مجاز Probe (CIDR)»**.
2. مقصد را اضافه کنید؛ یک آدرس خاص (`28.128.126.17/32`)، یک رنج
   (`28.128.0.0/16`) یا همهٔ مقاصد (`0.0.0.0/0, ::/0`) — با ویرگول جدا کنید.
3. «ذخیره تنظیمات» را بزنید؛ **بلافاصله اعمال می‌شود** (نیازی به راه‌اندازی
   مجدد نیست).

نکته: آدرس‌های Cloud Metadata (`169.254.169.254` و…) و Link-Local باز هم مسدود
می‌مانند؛ بازکردنشان فقط با متغیرهای محیطی `NETWATCH_PROBE_ALLOW_METADATA=1` /
`NETWATCH_PROBE_ALLOW_LINK_LOCAL=1` ممکن است. جزئیات: [security.md](security.md).

### متغیرهای محیطی پرکاربرد

```bat
set PORT=8787
set HOST=127.0.0.1
set NETWATCH_DATA_DIR=C:\NetWatch\data
```

فهرست کامل: [fa/04-configuration.md](fa/04-configuration.md).

## ۶. عیب‌یابی

| نشانه | علت و راه‌حل |
| --- | --- |
| `Node.js 22.12 or newer is required` | نسخهٔ Node قدیمی است؛ نسخهٔ ۶۴بیتی ≥ ۲۲٫۱۲ نصب کنید |
| `Missing .npm-cache folder` | بسته ناقص کپی/استخراج شده؛ فایل tar.gz را دوباره منتقل و باز کنید |
| `node_modules is missing` هنگام بروزرسانی | نصب قبلی ناقص است؛ ابتدا در همان پوشه `install.cmd` را اجرا کنید، سپس بروزرسانی را تکرار کنید |
| `npm ci` با `--offline` خطا می‌دهد | کش ناقص است؛ بسته را با `npm run offline:prepare` دوباره بسازید |
| `Missing native binary packages` | بستهٔ ساخته‌شده برای پلتفرم دیگری است؛ برای ویندوز x64 بسازید |
| `something is listening on 127.0.0.1:8787` | برنامه هنوز در حال اجراست؛ متوقفش کنید (یا در صورت اطمینان `--ignore-running`) |
| خطا هنگام بروزرسانی، **قبل از** مرحلهٔ کپی | چیزی تغییر نکرده است؛ خطا را رفع کنید و دوباره اجرا کنید |
| `npm warn deprecated jpeg-exif / crypto-js` | **خطا نیست؛** فقط اعلام بازنشستگی یک وابستگیِ غیرمستقیم؛ نصب سالم انجام می‌شود |
| `7 vulnerabilities …` پس از `npm install` | `npm audit fix` (بدون `--force`) آسیب‌پذیری‌های بدون تغییرِ شکننده را می‌بندد؛ باقی‌مانده معمولاً فقط ابزارهای توسعه (eslint) را می‌گیرد و `--force` نسخهٔ شکسته نصب می‌کند — انجام ندهید |
